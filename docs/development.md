# 개발 단계

각 Step은 **끝났을 때 사용자가 직접 실행·확인할 수 있는 상태**가 되도록 나눈다.
한 Step이 끝나면 PR을 만들고, 사용자가 확인·merge한 뒤 다음 Step으로 넘어간다.

## 현재 상태

- [ ] Step 1 이후 진행 전

> UI/UX는 사용자가 직접 설계한다. 아래 Step의 화면 구현은 사용자의 설계를 받은 뒤 진행한다.

## Step 목록

| Step | 내용 | 완료 확인 방법 | 외부 연결 |
|---|---|---|---|
| **0** | 프로젝트 기반 문서, 데이터 구조, mock 데이터 | 문서와 `data/mock/` 확인 | 없음 |
| **1** | React + Vite + TypeScript + Tailwind 프로젝트 생성, Vercel 첫 배포 | 휴대폰에서 빈 화면 주소가 열림 | GitHub, Vercel |
| **2** | 카카오맵 표시 + 현재 위치 + 서비스 지역 반경 표시 | 내 위치 중심 지도, 1.5km 원 | 카카오 JS SDK |
| **3** | mock 데이터로 마커 표시 (종류별 구분) | mock 마커가 지도에 보임 | 없음 |
| **4** | 추천 카드 + 상세 시트 + 외부 지도 앱 길찾기 | **핵심 흐름 완성** | 카카오맵 링크 |
| **5** | Supabase 연결, mock → DB | 대시보드에서 데이터 수정 시 앱 반영 | Supabase |
| **6** | 제보 기능 (`reports`) | 제보가 DB에 쌓임 | Supabase |
| **7** | 현장조사 데이터 입력, 정보 화면, PWA, 피드백 링크, QR | 게시판에 붙일 수 있는 상태 | — |
| **8** | 현장 테스트 → 피드백 반영 → 구로구 확장 | 피드백 이슈 정리 | — |

## 단계별로 사용자가 이해하면 좋은 것

| Step | 개념 |
|---|---|
| 0 | 저장소 구조, CLAUDE.md가 하는 일, 브랜치와 PR |
| 1 | `npm run dev`(내 컴퓨터 실행)와 배포의 차이, 환경변수(`.env`) |
| 2 | 위치 권한은 HTTPS·localhost에서만 동작, 카카오 도메인 등록 |
| 3 | 컴포넌트와 props, JSON 한 줄 = 마커 하나 |
| 4 | 추천 가중치(`product.md` 7절)를 바꾸면 추천이 바뀐다 |
| 5 | Supabase 표 편집, RLS(누가 읽고 쓸 수 있는가) |
| 6 | 제보 → 운영자 검토 → 반영 흐름 |
| 7–8 | 피드백을 이슈로 정리해 다음 작업으로 만드는 법 |

## 예정 프로젝트 구조 (Step 1 이후)

```
src/
├── main.tsx, App.tsx
├── config/areas.ts        # 서비스 지역 (중심 좌표, 반경)
├── types/bin.ts           # Bin, Report 타입
├── lib/                   # 거리 계산, 추천 순위, 길찾기 링크, 외부 연결
├── hooks/                 # 현재 위치, 쓰레기통 데이터
└── components/            # 지도, 카드, 시트, 공통 UI
```
